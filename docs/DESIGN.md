# scrollback: design spec

The chosen direction is **concept E**: A's sidebar, always present, beside B's folder page and reader, without B's timeline gutter (PLAN D12).
Pixel reference: the "Concept E" page of the design canvas (a private canvas), whose sources are the `E-*.dc.html` boards in `design/project/`. Each board has a `theme` tweak (dark / light). Tokens and shared components are in `design/project/sb.css`.
Behaviour lives in [FEATURES.md](FEATURES.md) and [PLAN.md](PLAN.md); this file is tokens, layout and interaction. Where a board and this file disagree, this file wins (§6 lists the known differences). Cite it as `DESIGN §N`.

### 1.3 Typography

- **UI:** Geist (bundled, OFL), fallback Segoe UI Variable / system-ui. 13px/18px body; 12px/16px secondary; 11px/14px counts, tags, keycaps and overlines; 500 for controls and names, 600 for titles; only 400/500/600 are loaded.
- **Overline** (`over`): 11px/14px, 500, letter-spacing .08em (not drawn yet, §6), uppercase, `fg3`. Section labels in the sidebar, facts margin and month groups.
- **Reading:** transcript prose 15px/24px; markdown inside nested panels and tool results 13px/20px; `h2` 17px/24px 600; `h3` 14px/20px 600; inline code 12.5px on `s3`, radius 4.
- **Code:** JetBrains Mono (bundled), 12px on 19–20px rows; line numbers `fg3`, tabular, right-aligned in a 30–36px gutter. Numbers in the UI (counts, dates, sizes) use Geist Mono with tabular figures. Inside proportional text only the digits take the mono face; a separator between them (`,` `.` `:`) stays in the words' face, since Geist Mono's comma is a digit wide.
- **Headings:** page title (folder, Unsorted, Trash, All sessions) 24px/30px 600; first-run and edge-state titles 22px/28px 600; sheet and dialog titles 15–16px 600; settings section 17px/24px 600.

Inline stroke icons at 12/14/16/18px, stroke 1.6, round caps and joins, `currentColor`, Lucide geometry bundled as SVG paths. No emoji anywhere. The set used: folder, folder-plus, folder-input (move), inbox, star, layers (All sessions), trash, rotate-ccw (restore), search, chevrons, arrow-left (back), terminal (Bash), file-text (Read), file-plus (Write), file-x (gone, damaged), file-search (Glob), pen (Edit), list-todo, bot (agent), lightbulb (thinking), image, globe (web), plug (MCP), puzzle (unknown tool), fold-vertical (compaction), refresh (sync), history (versions), monitor (Local), box (WSL), laptop (SSH), plus, ellipsis, git-branch, link (paths), filter, grid, list, triangle-alert, circle-alert, check, circle-check, copy, play, pause, clock, sun, keyboard, archive, ban (deleted for good), message (search result), calendar, external-link, grip-vertical (drag handle), eye, shield-check (verify), hard-drive, settings (gear).

**Tool kinds are told apart by icon and name, never by colour.** No view colour-codes tool kinds (the gutter and kind-mix bar of concept B are dropped for good).

**Agent and model marks.** A session shows its agent's mark beside its model wherever the model appears (§4.2.10, §4.4, §4.5, §4.9). Claude Code's sessions show the Claude mark in `claude`; each later agent (opencode, pi) brings its own one-colour mark, falling back to `bot` in `fg3`. As an avatar the mark sits on its colour at 14–16%.

- **Two regions only:** the sidebar and the main area. No status bar: sync state is in the sidebar foot. No session-list column: lists are pages in the main area.
- **Title bar:** the mark (an 18px `accent` tile with three `accent-ink` bars at 100/70/45%) and "scrollback" at 600; the search field centred on the window (a button that opens the palette, §4.9); Sync all (small button); Settings (gear, ghost icon button); the caption buttons, 46 wide and the bar's height, Close red on hover (Windows). On macOS the traffic lights sit at the left in a transparent titlebar and the mark moves right past them. A drag on the bar moves the window; a double-click maximizes or restores it.
- **Main area pages** (folder page, All sessions, Starred, Unsorted, Trash, Settings) have 20px top and 24px side padding, a header, then a scroll area. The page header and filter row stay put; only the content under them scrolls.
- **The reader** fills the main area: its 44px header, then the reading column (scrolls) and the facts margin (fixed; its Turns list scrolls on its own).
- **Minimum window size** 960 × 600.
- **Narrow windows:** below 1280px the facts margin collapses; a **Facts** toggle (panel-right icon) appears in the reader header and shows the margin as an overlay on the right edge, over the reading column, with `shadow-pop`, closed by `Esc` or a click outside. Below 1040px the sidebar collapses too: a sidebar button appears left of the mark and `Ctrl B` toggles it; it opens as an overlay over the main area, and picking a row closes it. Session cards drop from four columns to three, then two, keeping the 200 minimum. List-view columns drop in the order Branch, Location, Folder; Title never truncates below 240.
- **Overlays:** sheets (locations), dialogs and the palette sit over `scrim`, which covers everything below the title bar, and are closed by `Esc` or a click on the scrim. Popovers (versions) and menus have no scrim and close on `Esc` or a click outside.

## 3. Materials

Light and dark follow the siblings through `gpui_appearance` (PLAN D13): **System** follows the OS, **Light** and **Dark** force a mode. The window material follows the siblings too:

| Platform | Choices | Default |
|---|---|---|
| Windows 11 | Mica, Acrylic, None | Mica |
| Windows 10 | None | None |
| macOS | Vibrancy, None | None |

| Surface | Mica / Acrylic / Vibrancy | None (Opaque) |
|---|---|---|
| Window background | the OS material | `bg-app` solid |
| Title bar | `chrome` at 82% (Mica) / 60% (Acrylic, Vibrancy) | solid |
| Sidebar | `bg-side` at 76% / 50% | solid |
| Main area, reading column, facts margin | solid: reading never sits on a material | solid |
| Code, call bodies, cards, inputs | solid | solid |
| Sheets, dialogs, palette | `s2` solid over `scrim`; no blur | same |
| Popovers, menus | `s2` solid | same |

GPUI blurs only what is behind the window, so in-app overlays never frost app content; there is no backdrop blur anywhere. **None** is chosen automatically where the OS offers no material, with system transparency off, or with Reduce transparency on, and must look finished in its own right. `fg3` on the translucent sidebar over a contrasting desktop is unverified (§6). The window's inactive appearance is the OS's; scrollback dims nothing itself.

## 4. Screens

### 4.1 Shell: title bar and sidebar (every board)

- **Search field** (title bar): `field` style, 460 wide, search glyph, "Search titles, prompts, replies and commands", `Ctrl K` keycap. A click or `Ctrl K` opens the palette (§4.9). On the first-run screen it is hidden (§4.10); while the archive is unavailable it is disabled (§4.14).
- **Sync all** syncs every location (PLAN §5); while any pass runs its glyph spins and it reads "Syncing…", a second click does nothing. **Settings** (gear) opens Settings in the main area (§4.13).
- **Sidebar, top to bottom:** library rows **All sessions**, **Starred**, **Unsorted** (its count in `accent-text` while it is above zero), **Trash**, each with a count right-aligned in Geist Mono 11px `fg3`; the **Folders** overline with a New folder `+` (22 square); the folder tree; a spacer; a hairline; the **Locations** overline with a Sync all glyph; one row per location.
- **Rows:** 32 high, radius 8, icon `fg3`, name `fg2`. Hover: `s2`. Selected (the page shown, or the folder of the session being read): `s3`, name `fg` at 500, icon and count `fg2` (`fg3` falls short of 4.5:1 on `s3`, §1.1). Folder rows indent 18 per level with a 1px `line` guide, a 12px chevron for a folder with children (a click on the chevron opens or closes it without selecting).
- **Folder tree drag and drop** (folio's tree is the precedent, PLAN §11): drag a folder onto another to nest it, between rows to reorder (a 2px `accent` insertion line, indented to the level it lands at). Hovering a closed folder for 500 ms opens it. A row that would take the drop is the **drop target**: `accent-soft` fill, 1px inset `accent` ring, icon and count in `accent-text`. A folder can't be dropped into itself or its descendants, nor among siblings that already have its name (no target shows; the ghost says why). While a drag is held in a narrow window, resting on the sidebar button for 500 ms opens the sidebar, and it closes when the drag ends. The ghost is a pre-rendered row (GPUI can't rotate a div): `s2`, `line` border, radius 8, `shadow` `0 14px 30px rgba(0,0,0,.30)`, grip glyph, the dragged item's name, "→", the result in `accent-text`, and a `fg3` note on what it does ("files by hand", "attach to scrollback · files 3 sessions").
- **What drops on a folder row:** a session (card, list row, reader header title): files it there by hand. A path chip from Unsorted or a folder page: attaches the path. A folder: nests it. Trash takes sessions (moves them to Trash). Unsorted takes a session filed by hand only through **File automatically** (§4.4), never by drop.
- **Folder names** are unique among siblings, ignoring case: New folder takes the next free name ("New folder 2"), and a rename to a taken name stays open with a `bad` border and an inline note.
- **Dialogs** (Delete folder…, Save the path changes?) hold the keyboard until answered; no page or shell key acts behind them.
- **Folder row menu** (right-click or `⋯` on hover): Open, New subfolder, Rename (`F2`, in place), Edit paths… (opens its folder page with the path editor open, §4.7), Delete folder… (a dialog: "Delete *fc*? Its 447 sessions go to Unsorted and are filed again by the rules; its subfolders move up to its parent. Nothing is deleted from the archive."). A subfolder whose name clashes with its new siblings takes the next free name, and the toast says so ("Folder deleted; its subfolder work is work 2 now").
- **Location rows** (foot): 40 high, kind icon (monitor Local, box WSL, laptop SSH), name at 500 `fg2` 12px on a first line of its own, cut with an ellipsis, and a second line 11px: "Local · synced 2 min ago" (`fg3`, `green` dot at the right), "SSH · last sync 12 days ago" in `yellow` with an alert glyph and an outlined dot when unreachable and stale, "SSH · failed · host key changed" in `red` with an alert-circle glyph. Any location row, or the overline's area, opens the locations sheet with that location selected (§4.11). A location with more than one agent reads its sync state for all of them in one row.
  - **Busy** (syncing, or indexing outside a pass): 48 high, three lines 3 apart: the name; a 4px `accent` bar; then what is happening at the left in `fg3`, which gives way first with an ellipsis, and how far at the right in `accent-text` Geist Mono 11px, never cut. Fetching: "WSL · 41 of 96 MB" and "38 / 212 files"; scanning: "WSL · scanning" alone. Indexing (PLAN §7.5) makes the rows, and their text with them, and counts what it has left, never N / N: "Local · indexing" with "1,240 left"; a first sync's "first sync ·" gives way to the step once it indexes. It fills the bar. When the search index has text still to make after it (made anew, or text an earlier index could not write), that is a step of its own that fills the bar again from empty, "Local · search index"; with nothing to make, the bar stays full. With several agents at a location, each one's index fills the bar from its start. Two steps count nothing, and say their word with no count at the right: "compacting", over a full bar, when the index compacts the search index after it wrote much of it again; and "waiting", over an empty bar, when the index of every location waits for another index that has the backlog (PLAN §7.5). A location indexed outside a pass says "indexing" from the start, never "scanning".
  - **Session index**: while the index of every location runs (at a start, PLAN §7.5), a busy row of its own after the locations, layers glyph, "Session index", and under its bar why it runs: "after an update" when it reads again what another version of the parser or of the index made, else "every location"; then "search index" for its second step.
  - At the sidebar's 248 (the overlay of a narrow window is as wide) a third line is 191 across: about 117 of words beside "1,240 left", about 91 beside "38 / 212 files", and fewer as the count grows ("2,318 / 2,318 files" leaves about 58), since the words give way first.
- **Focus order:** title bar (search, Sync all, Settings, caption buttons), sidebar top to bottom, then the main area. `Ctrl B` or `F6` moves focus between the sidebar and the main area.

### 4.2 Reader (`E-Reader`, `E-Reader-Calls-1`, `E-Reader-Calls-2`, `E-Reader-Subagent`)

#### 4.2.1 Header (44)
Back (arrow, to the page the session was opened from, `Alt ←`); the breadcrumb: the folder (or Unsorted, Starred, All sessions, Trash) in `fg3`, a chevron, the title at 600 truncating at its end; Star (a toggle, `yellow` filled when on, `S`); previous / next session in the page it was opened from (`K` / `J`) and "4 of 488" in `fg3`; a spacer; the **Find** field (240, `Ctrl F`, §4.2.9); the **Activity | Full calls** segmented control (`E` toggles). The choice is remembered for the app, not per session. Below 1280 the Facts toggle joins the end (§2).

#### 4.2.2 Reading column
Max 720, centred, 28 top padding, 16 between blocks. Turns separated by a hairline. The column scrolls; the header and the facts margin don't. The list is virtualised (PLAN §9): collapsed activity rows have a fixed height, so a session with hundreds of calls has a known height. Opening a session shows the first turns from the index's offsets at once and fills in as parsing proceeds; while a later part is still parsing, its place holds skeleton rows (`s1` bars, 26 high) rather than a spinner.

- **You:** "You" at 600 `fg`, the time in `fg3` tabular, a Copy message button (22 square, shown on hover of the message and while focused). The prompt is rendered markdown at 15/24. Attached images follow as thumbnails (`shot`, 200 × 116, caption with the file name), a click opens the image full size in an overlay.
- **Assistant:** the agent mark, the model at 600, the time. Markdown fully rendered (FEATURES Reader): headings, lists, task lists, tables (`tbl`: `line` border, radius 8, header row on `s1` at 600 12px), block quotes, links in `accent-text` underlined at `accent-soft`, inline code, fenced code (`codeblk`: `code` fill, 28px `codehead` header with the language in mono 11px `fg3` and a Copy button at its right; plain until its highlights land, and plain for Kotlin and YAML, whose grammars aren't built in). Every row of a reply leaves the Copy column, so its pieces are equally wide. A piece that would be slow to lay out is drawn as plain text. A link whose text is an address (a scheme, or `www.`) and whose target goes elsewhere gets " (to host)" after it, or " (to another site)" when the target has no host to show. Control and direction characters show as visible markers (`⟦U+202E⟧`); a reply with nothing visible reads "(n blank characters)". Copy message on hover, as for You.
- **Selection:** text selects across blocks; `Ctrl C` copies it as plain text, as shown (markers included).

#### 4.2.3 Activity rows
One per tool call, 26 high, radius 6, full width less 8 each side: kind icon (14, `fg3`), the tool's name as its agent calls it, in mono 500 `fg` (44 wide; for Claude Code: `bash`, `read`, `edit`, `write`, `grep`, `glob`, `todos`, `agent`, `search`, `fetch`, `mcp`; `unknown` for a tool its provider doesn't map, whose own name is then the target; a longer name runs on into the gap after the column and, past it, ends in an ellipsis with the tool's own name on hover). The icon and the renderer come from the tool's kind (PLAN §7.4), which is common to all agents; only the name is the agent's. the target in mono `fg2` truncating at its end, optional status chip (`exit 101` bad, `4 passed` ok), the short result in Geist Mono 11px `fg3` ("5 matches · 0.1s", "+12 −5" in `green` / `red`, "37 lines", "Haiku 4.5 · 9 calls · 41s"), and a chevron (right when closed, down when open). Consecutive calls sit 1px apart in a group. Hover: `s1`; open: `s1`. A click or `Enter` on a focused row expands it in place: its body hangs under it, indented 30 (past the icon), and the rows below move down. Output loads when a row is first expanded (PLAN §9); until it arrives the body shows a skeleton of three lines. **Full calls** expands every row; collapsing one by hand in Full calls collapses only that one until the switch is flipped again.

A todos row shows the in-progress item and "1 of 4 done" in place of a target; an agent row shows the subagent's type and description.

#### 4.2.4 Tool renderers
Every body is a **call body** (`callbody`): `code` fill, `line-subtle` border, radius 6, optional **call header** (`callhd`, 26, `codehead`, 11px `fg3`, a Copy button at its right) and **call footer** (`callfoot`, 24, 11px `fg3`). Long bodies show their first 20 lines and "Show all" in the footer; a body never scrolls on its own inside the transcript.

- **Bash:** header `$ <cd and command>` in mono with Copy command; output 12/19 mono `fg2`, ANSI colours mapped to `green` / `red` / `yellow` / `blue`; footer: exit status (`red` when not 0), duration, line count, Copy output.
- **Read:** header: the absolute path and "lines 28–44 of 188"; content with line numbers, syntax-highlighted by the file's extension; footer "+n more lines · Show all". A Read of an image renders the image (below).
- **Edit:** dv's diff rows (PLAN §9, D15): hunk header on `hunk` in `blue`, rows 20 high with a 36px line number gutter and a 16px `+`/`−` marker on the gutter fill, word-level `add-word` / `del-word` marks, syntax highlighting over the diff fills. Unified only; the reading column is too narrow for split.
- **Write:** the same diff, every line added, "new file · 9 lines" as the short result; after 6 lines a `hunk` row "··· n more lines".
- **Grep:** header: pattern, path, mode, separated by `·`; matches grouped by file (the file in `fg`, each line with its number), the matching text in `hl`.
- **Glob:** the pattern as the target; body: one path per line.
- **Todos:** on `s1`: one 24px row per item with a 14px checkbox: done (filled `accent`, check, text struck through in `fg3`), in progress (`accent` outline with a 6px `accent` square), open (`fg3` outline).
- **Web search:** on `s1`: one entry per result, the title in `accent-text`, the domain and path in mono 11px `fg3`; "+5 more results".
- **Web fetch:** header "prompt" with the prompt given; the result as rendered markdown at 13/20.
- **MCP:** header: the full tool name in mono (`mcp__github__search_issues`) and "server github"; body: input and output side by side, each pretty-printed JSON with keys in `p`, strings `s`, numbers `n`, literals `k`, labelled "input" / "output" in `fg3`. Below 560px of column width they stack.
- **Unknown tool:** header "Tool scrollback doesn't know yet, shown as sent and received"; input and output as one-line JSON each, wrapping (D5: nothing is dropped).
- **Image a tool returned:** on `s1` with 10 padding: the image fitted to the column width, at most 320 high, and a caption (image glyph, name, "returned by Read", pixel size, file size, "Open full size").

#### 4.2.5 Thinking
Collapsed: one 22px row: lightbulb glyph, "Thought for 14s ·" and the start of the thought in italic 12.5 `fg2`, truncated. Expanded (a click; Full calls expands it too): "Thought for 22s" at 500 and a down chevron, the text below in italic 13/20 `fg2`, indented 22.

#### 4.2.8 Facts margin
268 wide, `bg-panel`, 18/16 padding, a left hairline. Three blocks separated by hairlines:
- **Session:** the facts one under another, 10 apart, each a **label above its value** (§6). The label is 11px/14px 500 `fg3` in sentence case: the overline without its capitals, so that it stays quieter than the blocks' own overlines. The value is 12px/16px `fg2` and takes the margin's whole width (236). In order:
  - **From:** the location tag; for a copy shown alone, the tag of the location it ran at when that is known (PLAN §7.7), else the copy tag (below).
  - **Copy** (PLAN §7.7; only for a copy, or for an original with copies, once per copy): lines, not a wrapped row. For a copy: the copy tag with the provider's label; "Kept on This PC."; where it ran: "Ran over SSH on user@macbook." when it is attributed to a location (that location's name), "Ran over SSH on buildbox." when its host resolved and is no location (the host as the app recorded it), else the provider's words ("Ran over SSH; the copy doesn't record which machine."); and while its original is archived, **Read the original**. For an original's copy: the copy tag; "Kept on This PC."; how it compares, "the same as the original", "behind the original" (both `fg3`), "longer than the original" or "differs from the original" (`yellow`, after the alert glyph), and for those two **Read the copy** on a line of its own (accent text, copy glyph).
  - **Path:** mono 11.5/16, one line.
  - **Branch:** the git-branch glyph and the branch in mono 11.5/16, one line.
  - **Agent** (only with more than one agent in the archive, §4.2.10): the mark and the name.
  - **Models:** one per line, each after the agent's mark (§4.2.10); past six, "and 14 more" in `fg3`, listing them on hover (at most 40, then how many more).
  - **When:** two lines: the day ("19 Dec 2025", the year only when it isn't this one), then the start and how long the session ran ("12:11 · 1 h 44 min").
  - **Tokens:** one line, "11.6M in · 297k out", numbers as everywhere else (Geist Mono, the short forms of §4.2.6).
  - **Version:** "v3 of 3", or "v2 of 4 · older" in `yellow`, then **History** (§4.3) on the same line, or on a line of its own where both don't fit.
  - **Source** (only when gone, §4.14): "gone since 12 Nov".

  **Nothing wraps.** Each line of a value stays one line; one too long for the width is cut with an ellipsis, never broken mid-word or across lines, and never inside a character. Path and Branch are cut to the width they are drawn at: the last folder of a path (after its last `/` or `\`) stays whole after the ellipsis with as much of the start as fits, and where even that doesn't fit, as much of each end as fits; the rest are cut in their middle. Path and Branch show their whole value in a tooltip on hover (mono, at most 480 wide, wrapping inside; past 4,096 characters it stops and says how many more). A click on either, or `Enter` once `Tab` is on it, copies it whole as it reads, one line, its controls shown and its line breaks as spaces, so that a value can't paste as commands; "Copied" shows in `accent-text` at the right of its label for a moment. The facts are not part of the column's text selection.

  **Copies** (PLAN §7.7). The **copy tag** is a `tag` with the copy glyph and the provider's label ("Claude Desktop's copy"), in `fg2`; it stands wherever a location tag would for a copy shown alone (cards, rows, Trash, search results, Unsorted's path chip, the paths editor, Settings' sessions deleted for good), never the tag of the machine that kept it. One whose host resolved and is no location carries the copy tag with the host as the app recorded it ("buildbox") in place of the label; its facts say "Ran over SSH on buildbox." under "Kept on This PC.". A host is drawn as a label (`hostile::label`), as any name a machine supplies. A copy read from its original stands for it: Back (`Alt ←`, the header's back button) returns to the original, and from there to the page; J / K and "4 of 488" go from the original's place; Star (and the star the header shows) acts on the original, as would anything else the reader offered to do to the session it shows.
- **Turns** ("Turns · 38"): one row per prompt: the turn number (on long sessions), the time, the start of the prompt truncated. The current turn (the one at the top of the reading column) on `s3` in `fg`; the others `fg2`. A click scrolls the column to that turn. On a session whose turns don't fit, the list scrolls on its own and keeps the current turn in view; `[` / `]` move to the previous / next turn. - **Calls:** one row per kind with its icon and count, labelled by kind, not by any agent's tool names (Shell, Read, Search, Edit / Write, Agents, Todos, Web, MCP, Other); a click filters nothing (hiding by kind is later, FEATURES Later).
