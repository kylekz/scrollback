Backfill is throttled

The backfill now runs through a bounded queue instead of spawning one task per cam, so a fresh library never has more than 4 yt-dlp processes alive.

  • Concurrency: buffer_unordered(CONCURRENCY) over the missing cams; nothing is spawned up front.
  • 429s: fetch_metadata maps yt-dlp's HTTP Error 429 on stderr to FetchError::RateLimited, and the loop waits with a doubling backoff.
  • Progress: Library health shows "Fetching metadata · 212 of 1,729" through the existing HealthItem::progress bar — see the subagent's finding.
